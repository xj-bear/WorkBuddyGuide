# 用真实日志生成周报并创建在线草稿

## 工作痛点与目标

**工作痛点：** 周报依靠回忆容易遗漏，自动生成又可能夸大进展。

**解决后得到：** 交付有材料依据的四段式周报与本人复核的在线草稿。

本周工作材料分散，需要提取交付、项目进展、风险和下周计划，再放到办公平台供自己审核。内容来自实际记录，不用空泛的量化指标凑成果。

## 开始前准备什么

- 建立「本周工作归档」，放入有权使用的会议纪要、分析结果、项目记录和备忘副本；标明本周日期范围。
- 没有完整周日志时先列出现有工作记录，缺材料就标缺。会议记录、任务清单和已交付文件只能证明其对应的实际进展，不能靠回忆补造业绩。
- 如需在线草稿，确认已接入办公平台、目标目录可写且可见范围明确；仅授予必要权限，授权不足时按提示确认具体缺项。

## 分步解决问题

### 1. 建立事实清单

在「计划」模式下限定目录与日期，先看哪些材料能用于本周周报。

```text
只读「本周工作归档」，日期范围为[填写起止日]。
先列材料清单，提取每项进展、对应文件或段落、实际日期、数字及状态。
区分已交付、进行中、计划和待确认，不把文件修改时间直接当业务发生时间。
材料不支持的成果、百分比、节省时间和项目结论不写；缺证据处明确标待补充。
先展示事实清单和重复项，等待我确认。
```

### 2. 用四段结构整理本地稿

确认事实后生成周报，核心成果少于三条时按实际数量写。

![周报四段式：核心交付、项目进展、风险资源、下周计划](/solve/20261018/10-02.png)

*结构示意：每项已发生进展有来源，下周计划由本人确认。*

```text
基于已确认事实整理周报：
1. 本周核心交付：写清交付物与实际结果，有依据时才量化。
2. 项目推进明细：项目名、本周状态、交付物文件名和来源。
3. 风险与需协调资源：具体卡点、影响、待确认负责人和需要支持。
4. 下周计划：区分材料明确的安排与建议，建议标待确认。
保留来源定位和待补项，保存「输出/工作周报-起止日.md」，不改原材料。
```

本人检查事实、敏感信息和下周承诺，将不适合共享的材料路径替换为接收人能访问的引用。尚未确认的计划不能写成已承诺交期。

### 3. 指定目录创建在线草稿

先通过已配置的连接器检查目标目录和权限；不要为了周报默认扩大到通讯录、审批或整个企业知识库。确认本地稿后再发创建指令：

```text
请把我审核过的「输出/工作周报-起止日.md」创建为新的在线文档。
平台与目录：[填已确认的个人目录或知识库位置]；标题：「工作周报-起止日」。
保留标题、列表和待确认标记，不新增事实，不修改现有同名文档。
如果发现同名文件先报告，不重复创建。返回新文档链接和可见范围。
只创建供我复核的文档，不发群消息、不@他人、不提交审批、不扩大分享权限。
```

*流程示意：“草稿”指待本人审核的文档，不假设平台一定有专用草稿箱。*
![飞书在线周报页面与任务记录](/solve/20261018/10-05.jpg)

*参考在线周报示例，用于说明交付位置，实际内容需根据本周材料重新生成。*

需要每周重复时，可先参考自动化基础教程固化日期、去重和输出规则。首次启用前手动测试，在线创建与正式提交保持明确的人为审核点。

## 检查交付结果

- 每项成果可回到本周材料；未完成、待补和建议没有被改写成已完成。
- 数字、项目名、日期和文件链接准确；不向目标文档带入不应共享的信息。
- 在线正文与审核稿一致，目标目录和可见范围正确，未出现重复文档。
- 正式共享、发送或提交由本人通读确认后执行；授权失效时保留本地稿，不能报告已同步。
