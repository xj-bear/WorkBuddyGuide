# 建立有来源的每日行业早报

## 工作痛点与目标

**工作痛点：** 每天重复浏览行业消息，新闻重复、来源和日期难以追踪。

**解决后得到：** 交付可追溯早报、手动试跑记录与受控定时配置。

定期收集指定来源的行业动态，合并重复事件并生成私人早报。先手动跑通，再启用定时；来源打不开、无新消息或数量不足都应如实说明。

## 开始前准备什么

- 自行准备可访问且有权订阅的RSS或来源网址、关注主题、排除项、时区和阅读频率。使用自己的RSS链接，个人订阅参数不要公开粘贴到共享文档或截图中。
- 明确本地输出位置、保留多久，以及任务运行所需电脑/客户端在线条件；以当前客户端任务说明为准，不能假定关机也会执行。
- 首次仅生成本人可见的本地文件。邮件、群聊等外发通知作为后续独立配置。

## 分步解决问题

### 1. 写明来源与筛选规则

先在普通任务里试跑下面的提示词。把占位说明替换成自己的实际RSS链接，不要使用他人的专属订阅参数。

![自动化触发时间、执行来源和内容、交付位置与通知三要素示意](/solve/20261018/09-01.png)

*自动化规则示意。*

```text
请读取这些指定来源：[填写自己的RSS链接或公开来源清单]。
按Asia/Shanghai时区检索过去24小时的AI产品更新、技术发布与政策消息。
每条保留标题、核心事实、来源名称、原文URL、发布日期与抓取时间。
按同一事件合并重复，剔除广告和无实质事实的推广；事实与影响判断分别写。
最多收录8条，不足5条按实际数量输出，不用旧闻、猜测或虚构消息凑数。
无法确认日期或打不开原文的内容列到「待核实」，不列为已证实新闻。
保存「输出/每日行业情报-YYYYMMDD.md」，附来源失败清单和筛选说明。
```

### 2. 手动验收后再设置触发

打开自动化入口，新增任务，填入经过试跑的指令、工作空间与时间。可选工作日08:30，并检查时区、日期范围与执行记录。若界面只提供周一到周五，它不等于法定节假日历；节假日与调休另行处理。

![WorkBuddy自动化任务列表与内置模板入口](/solve/20261018/09-02.png)

*参考入口界面；定时执行需检查实际运行记录。*

启用前手动运行一次，检查输出是否出现在指定目录、失败是否可见。给同一日期设置唯一文件名，约定已有文件时跳过或另存修订版，避免重复生成和重复通知。

### 3. 核对来源，再选择阅读格式

随机打开几条原文，核对日期、正文、标题和摘要。原文说的是预告时不能写成正式上线，来源观点也不能写成已证实事实。

![行业早报Markdown预览和条目摘要](/solve/20261018/09-04.jpg)

*早报版式示例；新闻日期与事实以本次采集并核验的结果为准。*

如果需要网页阅读版，可追加：

```text
把已核对的这份Markdown转换为本地HTML，保留原文链接、日期、待核实标记和免责声明。
不新增新闻或影响结论，不外发、不上传；输出与Markdown使用同一日期和修订标识。
```

![每日行业情报的HTML阅读页面及生成说明](/solve/20261018/09-05.jpg)

*参考阅读版，不证明定时任务或投递已成功。*

## 检查交付结果

- 每条事实有可打开的原文和明确日期，同一事件去重；条目不足时保留实际数量。
- 识别发布时间与事件发生时间，清楚区分转载、预告、传闻和已确认事实。
- 手动成功后才启用定时，检查后续运行日志、重试与断网结果；不在失败时沿用旧稿冒充当天。
- 早报与截图不包含个人RSS参数、访问令牌或未授权内容；需要外发时先核对接收对象和内容。
