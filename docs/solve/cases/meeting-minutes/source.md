# 把会议文字稿整理成纪要与待办

## 工作痛点与目标

**工作痛点：** 长篇转写混杂讨论和决定，责任人与截止日期不清楚。

**解决后得到：** 交付四模块纪要、可回溯行动项和待确认事项清单。

已经有会议文字稿，需要从口语讨论中提取结论和行动项，而不是把发言缩成另一份流水账。本方案从文字材料开始，不把录音转写能力当作前提。

## 开始前准备什么

- 准备获准使用的文字稿，最好保留发言人、时间戳、段落编号和会议日期。
- 若只有录音，先准备可用转写，并核对人名、术语和数字；原始录音与文字稿分开保留。
- 在「会议材料」中放文字稿与已有议程；参会名单未知时标明，不依据发言猜职位。

## 分步解决问题

### 1. 明确四模块和事实边界

新建任务选择练习工作空间，先提炼可审核的 Markdown 预览，再制作 Word。

![会议纪要四模块示意：基本信息、决议、分歧、行动待办](/solve/20261018/06-01.png)

*结构示意：讨论建议与最终决议分开记录。*

```text
只读「会议材料」中的文字稿与议程，去掉无关寒暄，但保留否定、条件和保留意见。
按四模块生成纪要预览：会议基本信息、按议题归纳的最终决议、遗留分歧与待定事项、行动待办。
每条决议与待办附来源文件及时间戳或段落位置；转写未提供时不要编造定位信息。
将建议、讨论、已确认决定区分开；同一议题多次修改时保留最终表态及未决之处。
只输出材料支持的内容，不给任务自行补负责人、截止时间或量化目标。
先保存「输出/会议纪要预览.md」和待确认清单，等待审核。
```

### 2. 把行动项做成能认领的表格

继续要求下面的字段。某人提出建议不等于由此人负责，会上提到某日期也不一定是交付期限。

```text
待办表至少有：序号、任务描述、主责人员、截止时间。
另加验收物、来源位置、待确认项，便于复核。
未明确责任人写「待指定」；未明确日期写「待会后确认」。
相对日期只有能结合已知会议日期确定时才换算，并保留原话；否则标待确认。
多个部门共同参与时，主责与协作分别写；只写「大家推进」不能推定个人责任。
```

![行动待办四列及未定事项标待确认的示意](/solve/20261018/06-03.png)

*字段示意：每项待办附来源位置与验收物，便于后续核对。*
![会议行动表含负责人、截止日期、验收物和缺失项，多项待确认](/solve/20261018/06-04.png)

*参考行动表示例：空缺应显式待确认，不为表格完整而补造。*

### 3. 审稿后另存文档

本人对照原文检查重要决定，确认后再要求：

```text
使用刚刚审核通过的纪要，不新增事实。保存为「输出/业务复盘会议纪要与待办.docx」。
保留模块标题、待办表和待确认标记；原始转写不修改。不发送邮件或群消息。
```

![会议纪要任务完成说明和文档预览中的未决事项](/solve/20261018/06-02.png)

*参考文档预览，可参考分块方式，不是原始转写读取画面。*

如材料已在办公平台，可再学习连接器方法；菜单中出现某平台只表示有入口，仍需确认实际账号、权限和可读范围。

![连接器菜单中腾讯会议、企业微信、飞书、钉钉等入口](/solve/20261018/06-05.jpg)

*参考连接器入口，不证明已完成授权或自动获取材料。*

## 检查交付结果

- 对照原稿检查决定、金额、日期、人名与否定表达，不能把「考虑」写成「已决定」。
- 待办均有可定位依据；责任人和日期缺失被明确标注，并由会议组织者确认。
- Word 打开后表格与标题正常，预览与最终稿一致，原文字稿仍可追溯。
- 正式分发和创建平台任务由本人审核后另行执行。
