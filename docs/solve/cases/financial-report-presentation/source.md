# 从公开财报整理六页汇报初稿

## 工作痛点与目标

**工作痛点：** 长篇财报难抓重点，汇报数字和结论又需要能回查原文。

**解决后得到：** 交付带页码依据的事实清单、六页大纲及人工审核的PPT初稿。

需要把公开财报整理成管理层可读的短汇报：先抽取营收、利润、现金流和风险，再将核验后的事实编排为六页。这里提供研究与表达方法，不代替财务专业判断。

## 开始前准备什么

- 准备公司公开发布且可读取的财报 PDF，确认文件清晰完整，并记下报告名称、期间、来源和版本。
- 确认是合并口径还是母公司口径、单位与币种、是否有重述，以及PDF页序与印刷页码是否不同。
- 说明汇报对象、要回答的业务问题、使用期间和六页的用途。只有一至两年可比数据时按已披露期间展示，不编造三年趋势。

## 分步解决问题

### 1. 在指定任务中读取报告并提问

可从专家/专家团入口选择适合的研究角色；能否读取财报应以当前任务实际附件与解析结果为准。先核对文件名、报告期间和目录，再问核心问题。

![WorkBuddy专家和专家团中心列表与精选场景入口](/solve/20261018/12-01.jpg)

*参考入口画面，没有展示财报上传或分析结果。*

```text
只根据我指定的公开财报回答，不补外部传闻或未披露数字。
先确认报告名称、报告期间、合并范围、单位和币种。
整理：营收/净利润及已披露同比；业务构成；经营现金流；管理层披露风险；重要口径限制。
每项数字与结论附文件名、章节、原文印刷页码和PDF页序（如两者不同）。
区分财报事实、管理层表述和分析推断；找不到的写「未披露/未找到」，不推测补齐。
输出「事实与证据表」，先不要做PPT，也不要给投资买卖建议。
```

![财报原文、问题提问、来源页码、人工回查的流程示意](/solve/20261018/12-02.png)

*核验流程示意：工具标出的页码仍需打开原文检查。*

### 2. 人工核验后确认六页大纲

先打开关键页，核对数字、口径和上下文。收入贡献不能等同利润贡献，净利润与现金流也不能互相替代。然后请求六页大纲：

```text
只用我核对过的事实表，先输出六页大纲，每页列核心观点、证据、拟用图表和待确认项。
1 执行摘要；2 核心财务表现；3 增长与业务构成；4 风险及限制；5 应对建议；6 所需资源/待决策问题。
趋势只用财报实际披露的可比期间；没有分部利润时不要把收入占比称为利润贡献。
第5、6页中的建议、目标、预算和资源申请均标「建议/待管理层确认」，不得当作财报事实。
没有依据的图表不画；资料不足时用缺口说明代替。
```

![从执行摘要、财务表现到风险、应对和资源支持的六页结构示意](/solve/20261018/12-03.png)

*结构示意：六页是本次表达约束，各页内容必须以实际材料和汇报用途为准。*

### 3. 根据审核大纲制作PPT

大纲确认后，再生成可编辑初稿，保留来源脚注。

```text
按我审核后的六页大纲生成「输出/财报汇报初稿.pptx」，不增加新数字与结论。
白底深蓝文字，每页一个观点，关键数字标单位/期间，图表附数据表与来源页码。
建议和待确认内容保留标记；信息不足的页明确写缺口，不用虚构数字填充。
另存「输出/数字与引用核对表.xlsx」，列PPT页、数字/结论、财报定位和确认状态。
保存后列出实际页数和仍待审核的内容，不把初稿描述为已获批准的正式汇报。
```

打开实际生成的PPT，核对是否恰为六页，各页是否对应审核后的大纲，并逐项对照数字与引用核对表检查内容。

## 检查交付结果

![数字对照原文页码、业务定调由人把关、最终汇报责任在人的示意](/solve/20261018/12-05.png)

*人工复核示意。*

- 核对表中每个数字能回到原文，期间、币种、单位、合并范围和同比基数一致。
- PPT确为六页，图表与事实表一致，脚注可读；打开检查字体、图表和文本溢出。
- 原文事实与分析推断、应对建议、资源诉求分清；单年或两年资料没有被扩成三年趋势。
- 重要财务解释与对外表达由合适的业务/财务负责人审核，本人准备追问所需原文依据。
